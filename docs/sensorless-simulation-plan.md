# 无感 FOC 软件仿真实施方案

- 状态：M1 有感基线和物理耦合的自整定参数验证已在 `software/foc-sim` 实施；M2–M5、配置场景矩阵和文中未来命令仍为拟定设计，不能当作当前功能。
- 代码基线：`76b72d3`，`chore/integrate-current-work`。
- 目标环境：Windows 主机 Rust；控制代码继续采用 Rust 2024 + Embassy / STM32G473RC。
- 本阶段不连接硬件、不烧录、不改变当前纯软件保护选择。

## 1. 决策与交付范围

以独立的主机 Rust crate `software/foc-sim` 作为仿真平台，直接依赖现有 `foc-firmware` 库。物理模型使用 `f64`，被测固件保持原有 `f32`。先用平均值逆变器与完整机械动力学验证控制算法，不引入完整 MOSFET 开关电路。

第一版交付的是可重复、可批量判定的闭环仿真平台，而不是无感功能已经完成的声明。按以下顺序推进：

1. 电机模型与现有有感 FOC 闭环。
2. 电压重构、采样延迟和非理想因素。
3. 无感观测器旁路运行，与真实状态比较。
4. 轻载启动、角度接管、中高速电流/速度闭环及失锁停用。

无感第一目标限定为 SPMSM 近似模型（`Ld = Lq`）、静止起步、空载或轻载、中高速运行。分别验证正向和反向启动，但不承诺运行中穿越零速的平滑反转。

暂不包含 HFI、零速带载、任意初始旋转状态接管、弱磁、MTPA、复杂磁饱和、完整功率器件开关仿真、热设计或 EMI。真实电机参数未知时，结果只对明确标注的合成参数有效。

## 2. 当前代码可复用内容与限制

### 可复用

- `software/firmware/src/control/foc_core.rs`：`FocController::step(RawAdcFrame, RotorSample)` 返回占空比、桥使能和遥测，适合主机端闭环调用。
- `software/firmware/src/interfaces.rs`：命令、采样帧、转子反馈与控制输出。
- `software/firmware/src/timing.rs`：100 kHz PWM / 200 ns 死区的单一配置来源。
- `software/firmware/src/autotune/` 与 `src/params/`：后续接入辨识和参数应用。
- 已有故障测试继续保留，作为控制器行为回归，不以新模型替代全部单元测试。

### 不能当成真实闭环仿真的部分

- `tests/autotune_flow.rs` 的开环阶段直接把 `plant.omega_e` 赋为设定电角速度；缺少转矩、惯量和负载决定的机械加速。
- 该测试部分路径以请求的 dq 电压驱动物理模型，没有统一经过最终占空比和桥使能状态。
- 上位机模拟器面向界面、会话及控制权验证，不是物理电机模型。
- 故障测试的部分配置使用 1 kHz 和缩短判定时间；不能据此宣称生产 100 kHz 时序已验证。
- 观测器/PLL 的自整定阶段只生成和检查参数；当前没有无感估算器或切换实现。

不删除或静默改变这些旧测试的语义。新建物理仿真，并把旧测试保留为流程测试。

## 4. 状态与信息隔离

划分四类数据，禁止把仿真真值误送给被测无感算法：

1. `PlantState`：真实角度、速度、dq 电流、转矩与机械状态，只由物理模型推进。
2. `SensorFrame`：经过偏置、量化、延迟与噪声的 ADC 数据，以及可选的模拟传感器反馈。
3. `ControllerView`：被测算法可见的采样、实际生效的占空比历史、母线测量和配置参数。
4. `TruthRecord`：仅供日志和验收器访问的真实状态。

`PlantParams` 与 `ControllerParams` 分别配置和序列化。对电阻、电感、磁链或采样增益进行扰动时，不能自动同步到控制器。

有感基准模式允许适配器用真值构造传感器反馈；旁路观测器模式允许控制器用传感器驱动，但观测器接口不能接收真值。无感接管模式禁止反馈真值，保护与接管判定也不得偷用真值误差。

物理模型的三角函数、坐标变换和积分使用独立 `f64` 实现及标准库，不复用被测固件的近似三角函数/变换函数；通过解析特例和能量关系避免双方共享同一符号错误而相互印证。

## 5. 电机与负载模型

### 5.1 坐标约定

与固件幅值不变 Clarke/Park 的物理约定一致：相电流正方向为逆变器流入电机，机械正转方向固定；机械角度、机械速度和电角度、电角速度分别保存，单位统一为 rad、rad/s。

令极对数为 `p`，则 `theta_e = p * theta_m`，`omega_e = p * omega_m`。物理模型不读取控制器的设定角度。

### 5.2 动力学

```text
 did/dt = (vd - Rs*id + omega_e*Lq*iq) / Ld
 diq/dt = (vq - Rs*iq - omega_e*(Ld*id + flux)) / Lq
 Te     = 1.5*p*(flux*iq + (Ld-Lq)*id*iq)
 domega_m/dt = (Te - Tload - B*omega_m) / J
 dtheta_m/dt = omega_m
```

模型支持 `Ld != Lq` 以便后续扩展，但首个观测器仅承诺 `Ld = Lq` 的运行范围。负载明确区分“固定方向的外力矩”和“阻碍当前旋转的负载”，不能用同一个符号在正反转场景中误充当助力。

首版使用固定步长 RK4，全部导数基于同一积分阶段的状态计算。控制周期 10 µs，初始物理步长 1 µs；以 0.5 µs 复跑检查收敛。1 µs 是起始选择，不是精度保证。

夹持转子只允许出现在明确的锁轴辨识场景中；运行/启动场景不能锁定或直接赋值机械速度。

### 5.3 合成基准电机

初始示例参数不是目标硬件或真实电机额定值：

| 参数 | 初始示例 |
|---|---|
| 母线 | 24 V，默认刚性电源 |
| 极对数 | 4 |
| Rs | 0.5 Ω |
| Ld / Lq | 200 / 200 µH |
| 永磁磁链 | 0.01 Wb |
| 转动惯量 J | 2e-5 kg·m² |
| 黏性摩擦 B | 2e-5 N·m·s/rad |
| 基准 Iq 目标 | 2 A |
| 软件电流限制 / 过流阈值 | 5 / 6 A |
| 机械速度测试点 | ±50、±100、±150 rad/s |
| 轻载测试力矩 | 0、0.015、0.03 N·m |

场景配置必须检查母线、目标电压/电流、欠压阈值和电机参数是否互相兼容。将控制器调参单独保存，不能为了通过测试偷偷改变真实模型参数。

## 6. 逆变器、采样和离散时序

### 6.1 平均值逆变器

只用 `ControlOutput.duty` 和 `bridge_enabled` 驱动模型，不用 `telemetry.voltage_dq` 作为实际施加电压。

桥使能时，设三相占空比均值为 `d_mean`：

```text
va = (da - d_mean) * Vbus_true
vb = (db - d_mean) * Vbus_true
vc = (dc - d_mean) * Vbus_true
```

加入定时器计数分辨率量化；换算规则与 BSP 的截断行为一致，计数范围根据实际计时配置核对。输入越界或非有限时记录契约失败，不能靠仿真端再次钳位掩盖控制器错误。

`PhaseDuty::DISABLED` 的 50% 占空比不等于断开功率桥，必须单独解释桥使能信号。

M1 的关断采用明确标注的理想化电流衰减模型，仅用于验证软件停用状态，不用于判断再生母线过压、二极管续流、关断峰值或停机距离。M2 若要验收这些工况，必须先增加可信的续流/二极管及母线储能模型；否则将相关指标标为“不支持”，不得给出通过结论。不能把桥关闭简单当成三相短接或瞬间清零电流。

### 6.2 事件时序

使用整数 tick / 整数纳秒推进虚拟时间，不依赖墙钟、不 sleep，不用浮点累加决定调度边界。

定义：在 `t_k` 采样的电流是此前实际电压作用的结果；同一时刻算出的新占空比不允许反过来影响该采样。

每周期约定：

1. 结算上一段已施加电压的物理积分。
2. 采集并锁存 ADC 帧，使用采样时刻的物理状态。
3. 先用上一段生效电压历史和当前采样更新估算器，再执行控制器。
4. 把输出放入带生效时刻的 PWM 更新队列。
5. 从当前时刻继续推进，跨越 PWM 生效时刻时切分积分步长。

默认先采用显式的一周期输出延迟作为测试契约，同时提供 0、0.5、1、2 个控制周期的延迟场景。默认值不宣称等同于实板；正式映射需核对 TIM1 中心对齐、重复计数器、CCR 预装载、ADC 转换完成与软件更新时刻。

保护停用可以按定义的停用延迟覆盖待生效输出，不能被排队的旧使能覆盖。丢帧场景允许物理世界继续前进，不得让“没有控制器调用”等价于“电机时间停止”。

### 6.3 ADC 与传感器

- 从真实 abc 电流生成 12 位原始 ADC 值，按配置加入每相偏置、增益误差、噪声、饱和及量化。
- 偏置校准在桥禁用、符合测试假设的状态下进行；校准后的偏置漂移单独测试。
- VBUS/TMP235 同样经过采样量化，不直接把真值交给控制器。
- 帧序号回绕、跳号和 `overrun` 走现有接口。
- 初版模拟传感器为理想角度反馈；编码器量化和 Hall 扇区反馈放到后续，不宣称已仿真真实中断和定时器。
- 可复现噪声使用固定算法和 seed，并记录算法版本；跨平台浮点结果采用容差比较，不要求任意平台逐位相同。

## 7. 无感算法接入路线

### 7.1 第一候选算法

选择 SPMSM 的 αβ 反电动势状态观测器 + PLL 作为首个候选，避免直接对带噪电流做数值微分。观测器估计电流和反电动势，PLL 输出电角度与电角速度。

不把当前 `observer_gain = bandwidth * flux` 当作已验证增益。实现前明确连续模型、离散化方法、增益单位和极点/带宽范围，通过独立开环信号测试后才进入电机闭环。

必须处理反电动势与磁极角的相位关系以及反转的 180° 歧义。低反电动势时估算无效，不能依靠 `atan2(0,0)` 或平滑 PLL 输出宣布锁定。

后续固件候选模块为：

```text
src/control/sensorless/
  mod.rs
  observer.rs
  pll.rs
  startup.rs
  voltage.rs
```

这些模块在 M3/M4 才新增，不属于 M1 平台搭建。

### 7.2 可见输入与输出

观测器输入：校准后的 αβ 电流、根据实际生效占空比和测量 VBUS 重构的电压历史、时间间隔、独立的电机参数估计。物理模型额外施加的未知死区误差不能直接作为已知量反馈。

M3 接入时从固件控制路径提供统一的已校准测量接口，复用偏置校准和电流换算逻辑，不在仿真适配器里复制一套“观测器专用校准”。避免读取本周期控制输出的遥测再倒灌给本周期观测器，造成隐藏的一拍延迟或代数环。

输出：估计电角度、电角速度、电流预测残差、反电动势幅值、有效性与锁定状态。

锁定判据只能使用算法可见信号，加入持续时间和迟滞；真值角度误差仅用于验收。启动初期允许根据已知拖动方向选择反电动势相位约定，但不能读取真实转向。

### 7.3 先旁路，再接管

M3 保留传感器驱动现有 FOC，观测器只记录估算结果。此阶段可以做误差分析，但不能声称已完成无感启动。

M4 才引入 `Align → ForcedCurrentRamp → Qualify → Blend → ClosedLoop → Fault/Stop` 状态机：

- 对齐与开环拖动采用受限电流，不直接沿用现有恒定 Uq 开环作为完整启动器。
- 观测器在拖动期间并行运行，达到可信度及速度条件后持续确认。
- 按最短角差平滑混合，妥善处理电流环和速度环状态，防止切换冲击。
- 失锁、启动超时或过流时停用；首版不自动重试、不直接切回大电压开环。
- 正反向起步分别验证；运行中反转与飞车接管属于后续范围。

角度来源与控制模式分离：电流/速度仍是控制目标，编码器/Hall/强制角/估计角是反馈来源。不把电角度直接塞进语义为机械角度的 `RotorSample`，也不把未锁定估算伪装成 `valid=true`。正式接口调整必须保留有感行为和既有回归测试。

## 8. 场景、指标与验收

所有阈值是拟定的仿真验收目标，不是当前测得结果，也不是硬件安全认证。场景启动前冻结验收窗口、阈值和参数；修改验收条件需在结果中记录，不能失败后静默放宽。

### 8.1 模型自身验收（M1 的前置门槛）

- 锁轴 RL 阶跃对照解析解；合理的非零参考区间内归一化误差目标 < 0.1%。
- 已知恒定转矩的机械加速对照解析解。
- 无耗散封闭模型中检查电磁/机械能量交换及数值漂移；有耗散时检查铜损、摩擦、负载功与能量平衡。
- 三相电流和约为零，独立坐标变换往返误差满足 `f64` 容差。
- 验证正负 Iq、正反转、负载方向的转矩符号。
- 1 µs 与 0.5 µs 步长的物理轨迹和关键指标收敛；非零峰值电流/速度的相对差异目标 < 1%，近零量用预设绝对容差。

### 8.2 控制场景矩阵

| 场景 | 目的与通过条件 |
|---|---|
| 启动偏置校准 | 校准完成前输出始终禁用；之后进入 Idle |
| 有感电流阶跃 | 例如 Iq 0→2 A→0；稳定后平均误差 ≤ 0.1 A，峰值不越场景限制 |
| 有感速度/负载阶跃 | 检查转矩与负载耦合；稳定非零目标速度误差 ≤ 5% |
| 开环轻载/超载 | 允许出现真实失步；不能通过赋值速度强制同步；失败必须可观测 |
| 旁路估算 | 两个方向、多个非零速度点；比较真实与估计电角度、速度 |
| 无感启动与接管 | 12 个初始电角度 × 2 个方向 × 3 档负载，共 72 个确定性组合 |
| 参数误差 | Rs 估计偏差 ±30%，L ±20%，磁链 ±20%；先单因素，再固定 seed 组合 |
| 采样误差 | 每相增益偏差 ±2%，校准后偏置漂移 ±2 ADC 计数，0/1/2 计数 RMS 噪声 |
| 延迟/母线变化 | 输出延迟 0/0.5/1/2 周期；母线按场景允许范围变化，并单独测试跨保护阈值 |
| 异常输入 | 丢帧、跳号、overrun、ADC 饱和、算法非有限状态；检查保护或明确记录缺失检测 |
| 失锁/停用 | 失锁判定后按规定周期禁用；后续旧命令和队列不得重新使能 |

参数误差矩阵用于建立可运行边界，不预先保证所有极端组合都能跟踪。场景分为“必须完成跟踪”和“允许安全退出”；不允许把本应跟踪的场景全部以停用算通过。检测不到的 ADC 饱和等行为必须成为显式失败/限制，不伪造已有保护。

### 8.3 无感的初始验收门槛（M3/M4）

在规定的中高速稳定窗口内，连续统计至少 200 ms：

- 电角度误差 RMS ≤ 5°，绝对误差 P99 ≤ 15°。
- 非零机械速度相对误差 ≤ 5%。
- 单次正常启动在 3 s 的场景期限内进入无感闭环并满足持续稳定窗口。
- 正常轻载场景峰值相电流 ≤ 5 A；超载场景单独检验软件保护，不以正常阈值强判全部通过。
- 接管时的估算/强制角差、混合进度、Iq 和峰值相电流全部记录；不能只以最终转速判断接管成功。
- 失锁采用拟定 5 ms 去抖上限；判定完成后下一次控制输出必须禁用，再按场景声明的功率桥停用延迟生效。该时间不替代更快的既有过流保护。
- 噪声场景先使用 10 个固定 seed；不保证成功的边界场景必须报告退出类型和保护延迟。

误差评估仅在有效性标记允许时不会掩盖启动失败：输出有效覆盖率、首次锁定时间及最长失锁时间。不能靠一直标记 invalid 消除全部误差样本而获得通过。

## 9. 日志、可重复性与命令入口

输出目录拟为 `software/foc-sim/runs/` 并加入 Git ignore。每次运行保存：

- `manifest.json`：软件版本、Git commit/dirty 状态、完整展开后的模型/控制/场景配置、seed、积分步长、时序假设、模型限制及配置摘要。
- `telemetry.csv`：时间、abc/dq 电流、最终占空比、桥使能、VBUS、真实/估计角度与速度、残差、锁定状态、启动阶段和故障。
- `summary.json`：通过/失败/不支持、指标、阈值、失败原因与时间。
- `events.csv`：命令、故障、锁定/失锁、切换和输出生效时刻。

验收指标按每个控制周期计算，不依赖抽稀日志。普通遥测可降采样到 1 kHz，故障前后保留有限长度的 100 kHz 环形缓冲，避免长时间运行生成无界文件。

未来从仓库根目录运行的示例（当前尚不可执行）：

```powershell
cargo test --locked --manifest-path software/foc-sim/Cargo.toml --target x86_64-pc-windows-msvc
cargo run --release --locked --manifest-path software/foc-sim/Cargo.toml --target x86_64-pc-windows-msvc -- run --scenario software/foc-sim/scenarios/sensored-current.toml --seed 1
cargo run --release --locked --manifest-path software/foc-sim/Cargo.toml --target x86_64-pc-windows-msvc -- suite --profile smoke
```

单场景阈值失败或 suite 中存在失败时返回非零退出码；配置错误与算法/模型失败在摘要中分别标明。仿真不依赖上位机在线或无线链路。

## 10. 分阶段任务与退出条件

### M1：可信物理模型与有感基线

新增主机 crate、配置、独立模型、平均逆变器、采样适配、调度器和基本日志；接入现有 `FocController`，不修改固件算法。

退出条件：模型解析测试、步长收敛、启动校准、有感电流和速度闭环通过；能观察到负载改变速度，而不是强制跟随指令。交付可复现的命令和场景，不要求漂亮界面。

### M2：非理想和时序基线

增加占空比量化、明确的输出/采样延迟、偏置/噪声、独立参数误差、平均死区电压误差及故障矩阵。平均死区模型只描述等效误差，不宣称解析 200 ns 开关波形。

退出条件：理想基线继续通过；时序因果关系测试通过；非理想因素开关和 seed 可复现；定义哪些停用/再生工况仍不支持。

### M3：旁路观测器与 PLL

在固件纯控制库中新增 `no_std` 观测器和 PLL，保持有感控制权。补充方向、相位、离散化和锁定单测，运行旁路误差矩阵。

退出条件：标称中高速与规定参数扰动范围内达到估算门槛，低速可明确拒绝有效性；两个传感器 feature 的现有行为和 ARM 构建不回归。

### M4：无感启动和接管

新增受限电流拖动、可信度确认、角度混合和失锁停用；调整反馈来源接口但不改变既有有感模式语义。实际硬件默认行为保持不变，无感硬件使能不随仿真完成而自动打开。

退出条件：72 个标称组合完成预期结果，规定噪声与参数偏差矩阵有可追踪结论；故障不会自动重新使能；所有已有单测和固件构建保持通过。

### M5：按证据决定扩展

只有中高速无感通过后，才评估 PLECS/Simscape 开关级对照、HFI、凸极电机、飞车接管、低速带载或真实电机参数导入。无需为第一版预先购买或依赖商业仿真软件。

## 11. 回归与验证边界

每个阶段运行新增主机测试，并保留现有固件测试、Encoder/Hall ARM release 构建与 Clippy；根目录 ARM 构建必须显式加载 `software/firmware/.cargo/config.toml`。主机仿真运行显式指定 Windows target，不得意外触发 `probe-rs` 烧录 runner。

软件仿真能证明：在所声明的模型、离散时序和扰动范围内，控制逻辑满足明确的指标。

软件仿真不能证明：STM32 在 10 µs 内的真实 WCET、实板 ADC 时序/噪声、栅极波形、死区、MOSFET 热性能、EMI、绝缘或故障关断安全。主机运行速度和 ARM 编译成功都不是 WCET 证据。现有 COMP→DAC→TIM1-BRK 保持未启用，不因新方案擅自增加硬件保护链。

本方案完成后的首个实施边界是 M1；不得把仅有感闭环或旁路观测通过描述为无感启动已完成。
