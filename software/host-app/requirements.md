# FOC 上位机需求与架构说明

> **文档状态：** 需求基线 v1
> **适用目录：** `software/host-app/`（规划中的上位机工程与桥固件）
> **对端固件：** `software/firmware/`（STM32G473RC FOC 固件，协议详见 `docs/software-design.md` §17–§19）
> **技术栈：** Rust + Tauri 2（桌面端）、Rust（桥固件，待定）
> **更新日期：** 2026-09-13

## 1. 目标与定位

上位机是 FOC 驱动器的**调试、整定与监控工具**，服务于以下场景：

1. 日常监控：实时查看电机状态、电流/电压/温度、故障位；
2. 参数管理：查看/修改运行参数，保存与恢复；
3. 自动整定：发起并跟踪一键 Auto-Tune 流程，展示辨识结果；
4. 波形诊断：记录并绘制遥测时间序列（类示波器），导出数据；
5. 受控操作：使能/禁用电机、设定目标值——必须带防误触设计。

**明确非目标**：不做电机控制逻辑的替代（一切控制指令仍由固件状态机裁决）；不做固件烧录工具（probe-rs 命令行已覆盖）；本轮不做多板组网管理。

**安全前提**：上位机与功率级之间没有电气共享。FOC 硬件**不直接**连接电脑，两种连接通道都必须提供隔离（见 §2）。上位机的任何操作都不能绕过固件的软件保护与安全门控。

## 2. 系统连接架构

```text
通道 A（有线，隔离 USB 适配器）：
  ┌─────┐   USB(CDC/WinUSB)   ┌──────────────┐   CAN 500k / UART 115200   ┌─────────┐
  │ PC  │ ├──────────────────┤│ 隔离 USB 适配器 │├──────────────────────────┤│ FOC 板卡 │
  └─────┘                     └──────────────┘     （适配器提供电气隔离）        └─────────┘

通道 B（无线，双 ESP32 2.4G 桥）：
  ┌─────┐  USB CDC   ┌────────┐    2.4G (ESP-NOW / WiFi)    ┌────────┐  UART/CAN  ┌─────────┐
  │ PC  │├──────────┤│ ESP32-B │├───────────────────────────┤│ ESP32-A │├──────────┤│ FOC 板卡 │
  └─────┘            └────────┘        （无线天然隔离）           └────────┘             └─────────┘
```

### 2.1 通道 A：USB 隔离 USB 适配器

上位机看到的都是一个**串口设备**（COM 口）。支持两种适配器形态：

| 形态 | 接口 | 上位机视角 | 隔离 | 备注 |
|---|---|---|---|---|
| UART 转 USB | FOC 的 USART3（PB10/PB11） | CDC 串口，115200 | 适配器内置隔离（如 FT232 + ADuM + 隔离 DC-DC，或成品隔离 UART 线） | 承载固件现有 ASCII 行协议 + 协议 v1 流 |
| CAN 转串口（slcan） | FOC 的 FDCAN1（PA11/PA12） | CDC 串口，slcan 协议 | 适配器内置隔离（如 CANable Pro 类） | 500 kbit/s；slcan 帧与固件 CAN 帧 1:1 映射 |

要求：

- **TR-A1** 适配器选型基线：支持 slcan 固件的 CAN 适配器（如 CANable 系列），上位机通过串口收发 slcan 帧；不依赖厂商闭源 DLL。
- **TR-A2** 上位机不假设具体型号，通过串口枚举 + 探测（发 `?`/版本查询看响应）识别通道类型。
- **TR-A3** 波特率/位速率固定：串口 115200；CAN 500 kbit/s。适配器侧可配置，上位机只暴露这两个值。

### 2.2 通道 B：双 ESP32 2.4G 无线桥

- **ESP32-A（板卡侧）**：与 FOC 板通过 UART（默认）或 CAN（TWAI，可选项）相连；与 ESP32-B 通过 2.4G 无线通信。
- **ESP32-B（电脑侧）**：USB 连接电脑，向上位机呈现 **USB CDC 串口**；与 ESP32-A 通过 2.4G 通信。
- 桥的本质是**透明隧道**：上位机与 FOC 固件之间的协议帧原样封装传输，桥不解析业务协议（只做成帧、校验、流控）。

无线链路技术选型（二选一，先 ESP-NOW）：

| 方案 | 延迟 | 可靠性 | 复杂度 | 备注 |
|---|---|---|---|---|
| **ESP-NOW**（推荐先做） | ~2–10 ms | 无内建重传，需自定义 seq/ACK/重发 | 低 | 无需 AP，配对即用；单帧载荷 ≤ 250 B |
| WiFi（TCP/UDP） | ~1–30 ms | TCP 可靠 / UDP 低延迟 | 中 | 需要组网（SoftAP 或局域网）；带宽充裕 |

桥固件要求：

- **TR-B1** 隧道成帧：`[MAGIC(2) | LEN(1) | SEQ(1) | PAYLOAD(≤200) | CRC16(2)]`；ESP-NOW 单帧放不下的协议帧必须分片（协议 v1 的单帧设计保证 ≤ 200 B）。
- **TR-B2** 可靠性：下行命令帧带 SEQ + 等 ACK（超时重发 ≤ 3 次）；上行遥测允许丢弃（帧内带 SEQ，上位机检测断流），但整定/参数响应类帧同命令一样走 ACK。
- **TR-B3** 配对：首次使用时按键/命令交换双方 MAC 并存储（NVS），之后点对点加密可选（ESP-NOW 支持 encrypted peer）。
- **TR-B4** 桥状态可观测：ESP32-B 通过 CDC 周期上报链路质量（RSSI、丢包率、缓存水位），上位机展示。
- **TR-B5** ESP32 选型基线：ESP32-S3（原生 USB CDC，免外部 USB-UART 芯片）；固件优先用 Rust（esp-hal + esp-wifi / ESP-NOW），如遇阻塞可退回 Arduino-ESP32，桥固件足够简单。
- **TR-B6** 断链行为：无线断开时 ESP32-A 不得向 FOC 发送任何半截数据（整帧缓冲、CRC 通过才转发）；恢复后从断点继续，不重放旧遥测。

### 2.3 传输抽象要求

- **TR-C1** 上位机内部定义统一的 `Transport` 抽象（Rust trait）：`open/close/send_frame/recv_frame/on_status`。三种底层实现：`SerialUart`、`SlcanCan`、`EspBridgeSerial`（ESP32-B 的 CDC）。
- **TR-C2** 应用层协议（§3）与传输层解耦：同一套业务逻辑通过任意通道工作。
- **TR-C3** 断线重连：传输层上报断开/超时，会话层自动重连（指数退避），UI 明确显示"连接中/在线/离线/数据过期"四态。

## 3. 上位机协议需求（协议 v1）

现有固件能力与缺口：

| 能力 | 现状 | 协议 v1 需求 |
|---|---|---|
| 状态/故障/三相电流/速度/温度 | CAN 0x180–0x182 @100 Hz ✅ | 保留 |
| **d/q 电压、三相占空比、瞬时母线电流、功率、目标值、NTC 原始值** | ❌ 任何通道都不发 | **新增全量遥测帧**（上位机波形诊断的硬需求） |
| 参数读写/保存 | UART `param ...` ✅、CAN 0x106/0x107/0x183/0x184 ✅ | 保留，补结果码表格化 |
| 自整定控制 | 仅 UART `autotune start/stop/status` ✅ | 保留；新增阶段事件推送 |
| 故障事件 | 仅轮询 | 新增锁存/清除事件帧（含时间戳） |
| 版本/身份 | 无 | 新增固件版本、协议版本、节点 ID 查询 |

- **PR-1** 协议 v1 分两个承载面落地：
  - **CAN 面**：新增遥测帧 ID（0x185：ud/uq/目标 iq/目标速度；0x186：三相占空比 + 瞬时母线电流；0x187：功率 + NTC + 节点 ID/标志），周期与 0x180–0x182 同步；事件帧按需发送。
  - **UART 面**：保留 ASCII 行协议（人工调试兼容）；新增二进制流帧（COBS 成帧 + CRC16），承载与 CAN 面等价的全量遥测与事件，流开关由上位机控制（`stream on/off` 语义）。
- **PR-2** 协议版本协商：会话建立后上位机查询固件的 `protocol_version`，不匹配时提示但尽力兼容 v1 子集。
- **PR-3** 节点寻址：CAN 面预留节点 ID 字段/ID 偏移（多板预留，本轮实现单节点 0）。
- **PR-4** 上位机必须容忍并统计：遥测丢帧（SEQ 跳变）、CRC 错误、超时；在 UI 呈现链路质量。
- **PR-5** 固件侧配合项（列入固件里程碑，不在上位机仓库实现）：新增 CAN 遥测帧、UART 二进制流、自整定/故障事件、版本查询帧。

## 4. 功能需求

| ID | 功能 | 需求描述 | 依赖 |
|---|---|---|---|
| FR-1 | 连接管理 | 枚举串口；选择通道类型（UART/SLCAN/ESP 桥）；连接/断开；自动重连；链路质量显示 | TR-C1~C3 |
| FR-2 | 实时仪表盘 | 状态机状态、故障位翻译表、三相电流、VBUS、结温、机械速度、d/q 电流，以数字面板 + 状态灯呈现，刷新 ≥ 20 Hz | PR-1 |
| FR-3 | 波形示波器 | 可选信号多通道叠加/分组绘图；环形缓冲 ≥ 60 s @100 Hz；暂停/缩放/游标读数；CSV 导出 | PR-1 全量遥测 |
| FR-4 | 参数管理 | 43 个运行参数按分组列表呈现；读/写带结果码反馈；save/load/defaults/factory-reset 按钮（带确认）；generation 与 dirty/restart-required 状态显示 | 现有协议 |
| FR-5 | 自整定向导 | 分步向导：前提检查（Idle、母线、传感器）→ start → 状态机可视化（19 状态 + 进度 + 错误码）→ 结果展示（rs/ld/flux/带宽/尝试次数）→ 保存确认 | 现有 UART 协议；事件推送为增强 |
| FR-6 | 控制操作 | enable(open/current/velocity)、disable、clear-fault、iq/velocity/open-loop 目标值设定；所有使能类操作需二次确认弹窗；输入值边界校验（与固件限幅一致） | 现有协议 |
| FR-7 | 故障与事件日志 | 故障位→可读名称；锁存/清除事件带时间戳；事件持久化到本地日志文件 | PR-1 事件 |
| FR-8 | 会话记录 | 自动把原始收发帧 + 解码事件写入本地文件（可关闭），用于问题回放 | — |
| FR-9 | 多通道并存 | 同一时刻仅允许一个活动连接（简化），但可保存多套连接配置（通道类型/端口/速率） profile | TR-C1 |

## 5. 界面需求

单窗口布局，左侧固定导航：

1. **连接**（顶部常驻：通道类型、端口、状态灯、重连按钮、链路质量）
2. **仪表盘**（默认页）
3. **波形**
4. **参数**
5. **自整定**
6. **控制**（或并入仪表盘的快捷区，带确认）
7. **事件日志**
8. **设置**（连接 profile、日志目录、界面语言[中文优先]）

风格：工程工具优先信息密度与可读性，深色主题默认。

## 6. 非功能需求

| ID | 类别 | 需求 |
|---|---|---|
| NFR-1 | 性能 | 遥测 100 Hz 全量流下 CPU 占用 < 10%（典型笔记本）；命令往返感知延迟 < 150 ms |
| NFR-2 | 带宽 | UART 二进制流按 100 Hz 全量遥测（≈ 40 B/帧）≈ 40 kbit/s，115200 波特下可行；超限时降级 50 Hz |
| NFR-3 | 可靠性 | 崩溃/断电不损坏任何持久化数据；日志写入失败不阻塞主流程 |
| NFR-4 | 安全交互 | 电机使能需二次确认；断线时 UI 置灰所有控制操作并显示"数据过期"；上位机永不发送超出固件限幅的值（本地同样校验） |
| NFR-5 | 跨平台 | Windows 10/11 优先（NSIS 安装包）；代码保持 Linux/macOS 可编译 |
| NFR-6 | 日志 | `tracing` 结构化日志，滚动文件；诊断模式可打开协议帧级日志 |
| NFR-7 | 可测试性 | `host-core` 协议编解码与传输抽象 100% 纯 Rust 可主机测试（复用固件仓库的测试文化） |

## 7. 软件架构（Tauri 2）

### 7.1 进程与模块划分

```text
software/host-app/
├── app/                      Tauri 2 应用
│   ├── src-tauri/            Rust 侧
│   │   └── host-core/        纯 Rust 核心库（无 Tauri 依赖，可独立测试）
│   │       ├── transport/    Transport trait + SerialUart / SlcanCan / EspBridge
│   │       ├── protocol/     协议 v1 编解码（帧、CRC、序列）
│   │       └── session/      会话状态机、环形波形缓冲、事件总线
│   └── src/                  前端（TypeScript + Vite）
└── esp32-bridge/             ESP32-A/B 桥固件（独立子项目）
```

- **host-core**：协议编解码、传输、会话、缓冲。所有与业务相关的逻辑都在这里，Tauri 只是壳——保证 NFR-7。
- **Tauri 命令（前端 → Rust）**：connect/disconnect、send_command、param_get/set、autotune_start/stop、waveform_fetch(时间窗)。
- **Tauri 事件（Rust → 前端）**：`telemetry-snapshot`（节流 ~30 Hz 的最新值）、`link-status`、`event-log`（故障/整定事件）。**波形数据不进事件流**——前端按需 `waveform_fetch` 拉取环形缓冲切片，避免 100 Hz 事件洪泛拖垮 webview。

### 7.2 技术选型

| 项 | 选型 | 理由 |
|---|---|---|
| 框架 | Tauri 2.x | 需求指定；体积小、Rust 后端 |
| 后端串口 | `serialport` crate | 跨平台 COM 枚举，slcan/CDC 通用 |
| 前端 | Vite + TypeScript + React 18 | 生态与招式成熟；图表库选择多 |
| 波形图 | uPlot | 时间序列性能最好（100 Hz 多通道无压力），体积 ~40 KB |
| 状态管理 | zustand | 轻量 |
| UI 组件 | 按需轻量组件（不引重型 UI 库） | 工程工具，深色定制 |
| 日志 | `tracing` + tracing-appender | NFR-6 |

### 7.3 关键数据流

```text
串口/CDC 字节流 → Transport（成帧/CRC）→ Session（解码/SEQ 统计）
  ├→ 环形波形缓冲（100 Hz，60 s）
  ├→ 最新值快照（30 Hz 节流）→ Tauri event → 前端仪表盘
  └→ 事件日志（故障/整定/参数）
前端操作 → Tauri command → Session → Transport → 固件
```

## 8. 里程碑

| 里程碑 | 内容 | 验收标准 |
|---|---|---|
| **M1 骨架 + UART 基础** | Tauri 脚手架、host-core 的 SerialUart + ASCII 协议、连接页、仪表盘（status 轮询 10 Hz）、参数页、控制操作（带确认） | 用现有固件（不改编译产物）通过 UART 完成参数读写与受控 enable/disable |
| **M2 协议 v1（固件侧）** | 固件新增全量遥测流（UART 二进制 + CAN 0x185–0x187）、事件帧、版本帧 | 固件测试更新；上位机接收全量遥测 |
| **M3 波形示波器** | 环形缓冲 + uPlot + CSV 导出 + 链路质量统计 | 整定 PI 阶跃过程可在波形页完整回看 |
| **M4 自整定向导** | FR-5 全流程 + 结果展示 | 通过上位机完成一次完整整定（仿真或台架） |
| **M5 ESP32 无线桥** | 桥固件（ESP-NOW 优先）+ EspBridge 传输 + 链路质量 UI | 拔掉 USB 线，仅经无线桥完成 M1–M4 主要操作 |
| **M6 打包与打磨** | NSIS 安装包、日志与设置页、异常路径打磨 | 非开发机安装即用 |

## 9. 开放问题（需要在实施前定案）

1. CAN 适配器最终选型（基线 slcan；是否额外支持 candleLight/WinUSB 直连？）
2. ESP32 桥固件框架终选：esp-hal（Rust）还是 Arduino-ESP32（快速验证）？建议 M5 先用最顺手的路径打通，再决定是否迁移 Rust。
3. UART 二进制流与 ASCII 协议的共存机制（帧头 magic 区分 vs 模式切换命令）。
4. 是否需要"ESP32-B 直连笔记本 WiFi 网页"模式（无上位机安装的轻量查看）——本轮否决，记录为远期。
5. 多板部署时的节点 ID 分配与上位机多连接（远期）。

## 10. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| slcan 适配器品质参差（时序、缓冲） | CAN 通道丢帧 | 选 CANable 系已知固件；PR-4 的丢帧统计暴露问题 |
| ESP-NOW 无线拥塞/丢包 | 遥测断流、命令重发延迟 | TR-B2 ACK 机制 + 上位机断流提示；必要时切 WiFi TCP |
| UART 115200 带宽边界 | 全量遥测降频 | NFR-2 预算已留余量；CAN 面不受限 |
| 100 Hz 事件洪泛卡顿 webview | UI 卡顿 | 架构上波形走拉取、事件走节流（§7.3） |
| 上位机误操作驱动功率级 | 硬件损坏 | NFR-4 安全交互 + 固件侧门控为最终防线 |
